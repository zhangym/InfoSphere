	 如何在选中文件夹位置打开Terminal窗口？

	1. 打开**系统设置 → 键盘 → 键盘快捷键 → 服务**，
	2. 在「文件和文件夹」分组，勾选：
		- ✅ **新建位于文件夹位置的终端窗口**（新建终端窗口）
		- ✅ **新建位于文件夹位置的终端标签页**（在现有终端开新标签）
	3. 点（在现有终端开新标签）右侧，设置自定义快捷键，例如 `Control + Option + Command + T`。
	「聚焦搜索」定位文件夹，选中「文件夹」，快捷键`Control + Option + Command + T`

- 202608251610 Mac Pro 里的 python 有好几个版本，问豆包，根据建议只保留系统自带的和安装的 anaconda 的。
	- 提示
		- Homebrew  python@3.14：yt-dlp 依赖它
		- Homebrew  python@3.13：pdftk-java 依赖它
		- uv 托管的 3.13.5：Anki、basic-memory、tavily-cli 都在用
		- uv 托管的 3.11： Hermes 在用
	- 查看：`uv python list`
	- 清理

```bash
# Homebrew 安装的卸载方法
## 1) 先卸依赖工具
brew uninstall yt-dlp
brew uninstall pdftk-java

## 2) 再卸 python
brew uninstall python@3.14
brew uninstall python@3.13

## 3) 清理残留
brew autoremove
brew cleanup

# uv 安装的卸载方法
uv python uninstall 3.12
```

uv 删除的几个 python 版本可能会导致部分文件无法使用，后面遇到问题再说。

- 202608251330（202608251720 Last upd.） 这两天看到[Mojo](https://mojolang.org/) 1.0正式版已发布，传说中比python快得多的 AI 时代的系统语言，决定尝试学一下。
	- 安装居然是作为 python 的一个模块：`pip install mojo`
	- mojo 可以引用 python 里安装的其他模块。但编译时发现在 VS Code 的Terminal里，编译提示找不到引用的模块，但在系统的 Terminal 中编译运行正常。问豆包，才知道是系统里存在多个 Python 环境造成的，并给了两种补救方案
		1. 临时：每次编译运行前，运行`export PATH="/opt/anaconda3/bin:$PATH"`
		2. 永久：让 VS Code 集成终端默认把 Anaconda 放到 PATH 最前。打开 VS Code 设置（`Cmd+,`），搜索 `terminal.integrated.env.osx`，点 "在 settings.json 中编辑"，加入：

```json
"terminal.integrated.env.osx": {
    "PATH": "/opt/anaconda3/bin:${env:PATH}"
}
```

			设置好后还是不起作用，问豆包，它帮修改了在 `~/.zshrc` 的 conda 块后面加了一行强制 Anaconda 前置：

```zsh
export PATH="/opt/anaconda3/bin:$PATH"

```
